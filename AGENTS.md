# Fake News Detection Project - Agent Instructions

Welcome to the Fake News Detection project. As an agent assisting with this repository, you must strictly follow these instructions to ensure consistency, prevent regressions, and respect the project's architecture and constraints.

## Project Structure
- **Entry Point:** `app.py` (Streamlit web application)
- **Source Code:** `src/` (Training, prediction, preprocessing, evaluation logic)
- **Tests:** `tests/` (Unit and integration tests)
- **Model Artifacts:** `models/` (Saved weights, vectorizers, vocabularies)
- **Datasets:** `data/`
  - Real labeled datasets: `data/raw/Fake.csv` and `data/raw/True.csv`
  - Synthetic demo data: `data/synthetic/` (Generated by `generate_modern_dataset.py`)

## General Guidelines
- **Understand Before Editing:** Always read the project documentation and understand the existing codebase before proposing or making changes.
- **Diagnose and Reproduce:** Diagnose reported problems by reproducing them when possible, tracing the root cause, and fixing the underlying issue rather than applying superficial patches.
- **Focused Edits:** Make focused changes, preserve unrelated user edits, and avoid replacing or deleting user files unless the task clearly requires it.
- **End of Task Summary:** At the end of each task, summarize the cause, the changes made, the verification steps taken, and any remaining limitations.

## Environment and Execution
- **Environment Checks:** Check Python, the virtual environment, and dependencies before running the app, training, or tests. Provide clear setup steps to the user if something is unavailable.
- **Running the App:** Run the Streamlit app from the repository root using the project's supported environment (`streamlit run app.py`). Report the exact command and any errors you encounter.
- **Testing:** Add or update tests when appropriate, run relevant checks, and accurately report what passed, failed, or could not run.
- **Documentation:** Update the `README.md` whenever setup, launch, or training instructions change.
- **Commands:** Use commands and paths actually found in the repository. Do not invent non-existent scripts or tools.

## Data Management
- **Use Real Data Only:** Train **only** from the real labeled datasets (`data/raw/Fake.csv` and `data/raw/True.csv`). 
- **Validation:** Validate required columns, labels, empty rows, class balance, and duplicate or repetitive examples. Stop and provide a clear error if the data is unsuitable.
- **No Placeholders:** Never replace real data with generated or placeholder data. 
- **Synthetic Data:** Keep synthetic demo data (created by `generate_modern_dataset.py`) separate under `data/synthetic/` and label it clearly. **This data is demo-only and must never be used for real training or evaluation.**
- **Prevent Leakage:** Prevent train/test leakage by identifying and removing duplicate or near-duplicate articles. Explain meaningful evaluation limitations if data quality is lacking.

## Model Training and Preprocessing
- **Consistency:** Keep preprocessing consistent across training and prediction. Verify that models, vectorizers, vocabularies, tokenizers, and label mappings (`1` for Fake, `0` for True) are compatible.
- **Train All Models:** When training or retraining is requested, you must train **all supported models**. This includes:
  - Traditional machine-learning models (e.g., Logistic Regression, Naive Bayes, SVM, Random Forest) via `src/train.py --tier all`.
  - Deep-learning models (e.g., LSTM and BERT) via `src/train_hardcore.py` when dependencies and compute are available.
- **Partial Training:** If any model cannot be trained (due to missing dependencies or compute), explain exactly why and what remains. **Never say all models were trained if only some were.**
- **Prediction History:** Initialize and preserve the database and prediction history correctly as implemented in the project.
